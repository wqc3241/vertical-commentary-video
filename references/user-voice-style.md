# 账号口播风格：从用户改稿直接生成

来源：2026-10-11《郑钦文中网首冠》完整口播阅读版的8段用户编辑，对照该项目保存的原canonical。
适用于这个账号的网球人物、赛事回顾与分析口播。下列是表达偏好，不是已验证的涨粉/留存结论；
本期明确要求优先。不要把这一期的8段结构、具体排名、比赛结论或措辞固定到其他选题。

## 从实际编辑提炼的写法

| 用户实际改动 | 生成时采用的原则 |
|---|---|
| “从世界第160，到……”→“郑钦文拿下中网冠军！成为中网第一位中国女单冠军！” | 夺冠/突破类先报人物与最重要的结果，然后解释意义；低谷经历放在背景段。用事实本身抓人，不强制先设问。 |
| 删掉开场“1发只有38%的决赛，她怎么把冠军赢下来了？”；补“创造了历史！” | 开头可以是有依据的喜悦和肯定。技术问题留在分析段，不每段预告“更值得拆开看的问题”。“首个/历史”仍须核查具体项目与范围。 |
| “前面有这样一段重新积累的过程”→“所以中网的爆发，并不是没有预兆” | 用自然承接把经历与当前表现接上，少堆“过程/竞争力”等抽象名词。可以说明有此前积累，不能仅凭先后断言某次训练必然导致冠军。 |
| 在二发得分数据后补“而这正是令人欣喜的部分”；补“依然能够找到机会下分” | 数据之后解释它意味着什么，并说出有依据的评价。把能力落到得分、相持、进攻等比赛动作，别只报数值。 |
| “包办了首盘最后11分”→“连续拿下了首盘最后11分”；“回合里”→“相持中” | 采用准确、常用的球友表达，少用新闻腔。专业词可以保留，陌生术语要解释；不故意塞“下分”等行话。 |
| “得分不能只靠一种方式”→“毕竟想赢比赛还是得有多种手段”，并补进攻/防守说明 | 让判断听得懂，说明手段的用途与条件。具体落点、旋转、防守效果须对应画面，不能从赛果凭空写出技术动作。 |
| “她没有让刚才的失误决定下一分怎么打”→“她最终拿下这个意义非凡的冠军！” | 关键局叙述落到赢局、赢盘或夺冠结果，给结果分量；少推测运动员内心。未经本人表述不写心理归因。 |
| 抽象“把竞争力……带回关键分的过程”→“一枚见证她低谷之后，一点点找回自己的勋章” | 总结可用一个与经历贴合的形象表达传达情绪。少量即可，不把整篇变成励志句、泛化赞美或生造比喻。 |
| 删掉发球/相持/关键分三选一，改为“看来又可以期待一下大满贯的表现了！” | 冠军/复出故事以相关的期待自然收束；讨论型内容按需要提问。取消“结尾必须提问”，不为互动硬塞问题，品牌CTA仍独立保留。 |

用户保留了大量比分、具体得分过程与完整段落，还增加解释与情绪。不要把偏好误读成“数据越少越好”
或“每句都要很短”。总体顺序可为结果→简要背景→本次经历→关键分析→意义与期待，具体结构依brief。
句间用“之后、所以、但、虽然、接着、而当”等按真实关系承接，避免句子突然跳转，也不逐段机械套同一连接词。

## 首稿提示块

在用户自己的ChatGPT项目中，连同本期brief、核实事实清单、发生/发布日期和目标时长，放入同一次请求。
不要生成第二份本地替代稿再拼接。下面内容用于引导首稿，按本期主题调整，不能填入本期事实清单没有的数据：

> 按这个账号球友聊天式的口播风格写完整稿。若是夺冠/突破类，开头先直接说人物和最重要的已核实结果，
> 接着点出其意义，可以表达有依据的喜悦；背景经历放到后面，不强制开场抛问题。讲经历时自然承接，
> 比分、统计和关键回合之后解释它说明什么，给观众听得懂、有依据的判断，少用抽象“过程/竞争力”总结。
> 采用“连续拿下、相持、找到得分办法”等自然且准确的比赛表达，保留完整句子和自然的语义段落，
> 不把正文按短字幕逐条切碎，也不要每段都写预告或励志金句。关键局最后落到实际赢局、赢盘或夺冠结果，
> 不替运动员编心理。冠军/复出故事结尾回扣经历和奖杯意义，再留下相关赛事的期待，不硬塞三选一或“你觉得呢”；
> 讨论型内容需要时再自然提问。不要机械复用这些示例词句。事实与作者评价分别写清，评价仍要有证据，
> 期待不保证未来结果。严格按核实清单使用“首个”、排名类型、比赛完成/退赛和日期等条件；
> 若某个细节不确定，留在核查备注，不写进正文。显示文本用阿拉伯数字，标点与分段服务真人口播。

品牌片尾 `关注我，了解更多网球故事和知识。` 单列，不强制把它塞进正文的结论/期待句。
以上风格块不替代主skill的事实核查、读音确认与脚本/素材批准步骤。

## 送审前检查

- 夺冠类是否先报最重要结果，再进入背景？开头有事实支撑的情绪，而不是夸张或一串预告。
- 经历与比赛是否自然接上？数据/回合后是否给出具体含义，避免只用抽象名词评价。
- 关键局是否落到实际结果？心理、战术和因果判断是否各有相应证据，不因删掉“我的理解”就升级为事实。
- 总结是否贴合这一场？结尾期待或问题是否自然，是否又被旧模板补回硬性三选一。
- 通读是否像完整讲话？顺手修正漏字或重复，如“敢于勇敢进攻”→“敢于进攻”，但不把用户语气改回公文。
- 本期事实范围是否仍准确？例如对手决胜盘退赛时，“打到了第3盘”不能顺口写成“打满3盘”。
- 用户改稿后各显示/配音视图是否来自同一版本，批准状态是否对应这一版本？

## 用户改稿的版本处理

先保存当前用户文件的原样快照与未改动的原canonical，逐场景比较；没有可靠基线时只分析当前表达，
明确不能归因哪些是用户新改的。提炼真实变化，不凭“更口语化”几个字概括，也不将每个新增细节当作事实。

如果用户只改了“连续阅读版”，下方 `vo`、字幕、发布引用或canonical可能仍旧。比较阶段保留用户原文件，
记录差异与待核实细节，在项目状态标明旧配音/字幕不能使用；不要静默把旧区当成已批准的新稿。
进入后续制作时，先落实事实修正与对应版本的脚本批准，再同步唯一canonical与所有派生视图、读音表和时长估算。
只做显示数字→已核准读法等必要转换，保留批准的句子、标点和语义段落；字幕换行不新增配音停顿。
用户要求比较、学习写法或固化skill本身，不等同于批准新脚本、素材、TTS或发布。
