# 口播审稿与制作返工

## 口播与包装

在送审口播、重做标题封面时读取本节。

- **主线：** 用一句话写出观众会追问的问题。人物片可围绕“为什么现在更强”组织等待、伤病、复出与变化；事实不支持时不要硬套成长故事。每段应带来新信息、转折或对主问题的回应，删掉只增加履历长度的比赛清单。
- **Hook：** 前2–3句明确人物、已核实的反差和继续看的理由。悬念必须在后文得到回应，不能把相关性讲成因果，例如不能仅凭时间先后断言宣布退役使成绩变好。
- **听感：** 通读完整口播，检查长段数据、重复解释和突然出现的观点。内部核查备注留在研究记录，口播中的必要限定改成自然表达；不要为了顺口省略会改变事实的条件。
- **结尾：** 问题从前文经历自然长出来，邀请具体经历或不同看法，避免空泛的“你觉得呢”。给仍在等待、没有成功转折的观众也留下回答空间；正文到问题结束，品牌 CTA 另接独立尾音轨。
- **时长：** 4–5分钟是成片长度目标，结合当前音色的实测语速估算稿长并预留独立片尾。记录估算与 TTS 实测；未经测量不要宣称改稿提升了留存或完播率。
- **包装：** 把发布标题、封面主副标、片头 chip 拿出正文单独读。人物仍在比赛时，“告别时，排名第17”容易读成已经退役，应改成明确的当前状态。三处一起修正，生成双比例封面后分别看图验身份、错字、脸部遮挡及标题完整性。

## 素材窗口

在素材门、延长剪辑窗口、重构图或重新配音改变时长后读取本节。

- 保存每个实际使用窗口的来源、赛事/年份、起止时间与身份依据；采访画面来源和引用文字出处分别记录。
- 抽窗口首、中、尾及内部镜头切换前后，特别核对赛后庆祝、挥手、握手、颁奖：镜头可能转到对手。获胜并不说明随后的每个近景都是冠军。
- 用重构图后的实际文件复核跟踪对象。延长窗口必须检查新增部分，不能沿用旧窗口的通过记录。
- 近期训练不能伪装成过去的康复过程。没有对应画面时，选择不会制造时间误解的经核实素材并明确语境，或调整画面方案。

## 声音核验误报

报警时保留原始 WAV、ASR JSON、文本差异和时间戳，先听对应位置。区分实际错读与校验器问题：

| 现象 | 检查与修正 |
|---|---|
| 普通数字被逐字展开，相似度骤降 | 普通数值用中文基数，如169→一百六十九；年份按口播读法处理。长序列比对检查 `SequenceMatcher(autojunk=False)`，避免常见音节被忽略。 |
| `第17 23岁` 被报成数字合并 | 数字邻接检测保留空格和标点边界；正确 `17 23` 不能误报，真实将 `250。8` 读成 `258` 仍应拦截。 |
| 繁简体、同音字导致错位 | 对照原音及上下文，不仅凭字符差异改声音。需人工通过时绑定音频哈希、秒段和理由；音频变化后复核失效。 |
| 句末字时间戳拖进尾部静音 | 结合真实静音起止核验发声边界，不按静音中点机械计字；不能用 ±1字容差消掉真正的词中停顿。 |

校验器修正应同时用“原来的误报”和“真实错读/词中停顿”验证，证明误报消失且实际错误仍被拒绝。
不要因报警无限重生成，也不要只为让检查变绿降低阈值。通过后继续使用原来正确的音频。

## 制作更新与局部修复

- 更新 skill：先读 Git 差异与项目定制，标明哪些批准仍有效。口播未改则沿用脚本批准；视觉更新只重做相关预览。
- 布局：字幕、标题、数字人、片尾作为同一画面检查安全区。数字人尺寸变更后按实际输出计算遮挡，不照抄固定字幕底线。
- 引擎或抠像参数变化：先做约3秒短样，检查透明边缘、白描边、脸部、嘴型及实际输出路径，再跑长片。运行参数优先在项目/进程内设置。
- 音频拼接：保留已批准段落的口播起点；时间线按目标帧率对齐，连续 PCM 母带后统一编码 AAC，检测接缝与音轨空洞。
- 按样本数裁剪前先显式统一采样率。例如44.1kHz素材参与48kHz母带时，先重采样再 `atrim`；尾差修复可重混音并复制视频流，不必重做画面或数字人。
- 修复后验证实际成片长度、帧数、音轨连续性和受影响窗口。没有变化的重型检查不重复跑，字幕/时长/素材窗口变化则重验对应依赖。
