# 双平台流量、涨粉与观察流程

用户问数据表现、涨粉与时长/图文关系、历史高表现封面，或要求“先观察再改”时读取。
这是只读分析路径，不执行脚本生成、配音、渲染、封面更换、重传、删除、申诉、改排期或创建定时任务。
用户另有明确行动授权时按其范围执行；讨论建议本身不扩大授权。浏览器按用户指定（例如 Chrome）经 CUA 使用。

## 先固定范围与版本

- 明确上传/发布时间范围与指标窗口：过去90天发布的作品，和后台过去90天流量筛选不是同一范围。
  记录账号、平台、采集时间/时区、各字段更新截止时间、发布时间与发布后天数；页面没写时区不要猜。
- 按作品ID对齐两平台标题和本地视频版本；记录时长、图文/视频格式、题材、人物/赛事、热点日期、
  实际封面主副标/缩略图、发布正文/话题、数字人模式和改版时间。用已有真源，避免另造冲突状态表。
- 当前版本保留本地视频/封面哈希与脚本版本，平台侧保留实际缩略图、标题、状态和管理页证据。
  后续修改会重新审核或改变时间窗口，不能混入原版结果。
- 原始数据来源必须明确：真实后台详情、用户提供导出或本次保存页面。旧下载表和历史快照标旧日期，不能冒充当前数据。
  受限/禁止播放/未到排期/审核中与正常已发布分开；指标缺失记null/不可用，不填0。

## 分平台、分链路分析

| 位置 | 指标/材料 | 能说明什么 |
|---|---|---|
| 分发入口 | 曝光、播放/观看、推荐/搜索来源 | 看到了多少人/从哪里来；不能单凭播放定封面好坏 |
| 点击 | 平台原生封面点击率、实际主副标/照片 | 包装吸引力；不能用观看÷曝光替代原生指标 |
| 开场 | 2秒退出、5秒留存/5秒完播等原生字段 | 是否接住封面承诺，明确字段是留存还是流失 |
| 内容 | 平均观看秒数、实际时长、完播率、留存曲线 | 何处流失与内容节奏；缺少曲线不反推精确掉点 |
| 行为 | 赞/藏/评/转、平台归因涨粉 | 共鸣、使用价值与转粉，涨粉不是账号净增粉 |

- 小红书与抖音分别报告，保留平台字段名称/分母。可比趋势并列，不把不同观看/关注归因定义强行相除宣称若干倍。
- 涨粉绝对量与每千观看归因涨粉都列：`归因涨粉 / 平台观看或播放 * 1000`，分母>0且同窗口才算。
  缺失不算，0播放的率不可用；万为单位的约数标近似。1–4人等小样本不称涨粉爆款或稳定规律。
- 高播放样本与高涨粉样本分别找共同特点；封面、正文、题材、口播开场、留存和关注理由一起看。
  没有脚本/实际声音证据时不能仅凭早期流失断言配音或数字人是唯一原因。
- 旧作品累计时间长，新作累计时间短。优先同一发布后24/72小时窗口；只有累计快照时明确窗口不同，
  不把差异换算成“改封面使流量下降X%”。下次采集记录累计与增量，增量不当成发布后早期指标。

## 时长与图文/视频关系

1. 先分平台，并按同类题材/人物热度、发布日期、观察时长和实际播放规模检查可比性。
   视频时长可按样本分布分组，报告每组作品数、中位观看/留存、涨粉绝对量及转粉率，不能只比总粉丝数。
2. 同一批都在3–4分钟、范围很窄时不足以判断“越短越涨粉”；短视频的高完播也不代表更高关注价值。
   没有足够长短样本或受控比较时只报相关观察，不给因果结论，不自行推翻用户深度时长要求。
3. 加入图文时标注格式、图片数、文案结构和可见阅读/收藏/关注指标。图文不能套视频留存/完播；
   缺指标单独列。比较同题材、同成熟期的阅读/播放与每千相应观看转粉，同时说明口径限制。
4. 不把选题热度、粉丝基础、日期、热点过期程度混成“图文一定比视频好”；样本不足就说明不足，
   列下次需收集的可比样本，不为证明结论补造数据。

## 历史封面与口播诊断

- 按 cover-design.md 读取高播放与高涨粉作品的真实封面主/副标、人物识别与布局，发布标题只作另一个字段。
  记录其具体信息如何吸引人，不把字数、某张照片或统一字体当单一成功原因。
- 结合脚本时间线标出“提出本期问题”“第一条判断/可用方法”“正式技术案例”的实际秒段，
  与原生留存/平均观看并列分析。可以指出观众通常未到技术章节，不能从均值推算精确流失人数。
- 检查口播日期是否符合发布时间，是否先串赛果/数据/核查套话才讲到核心；检查封面承诺与第一句话是否相符。
  问题已证实与改法有效是两件事；读音、断句问题须由实际文本/音频核实。
- 下一轮候选假设可以是“更早给出矛盾与证据、前20–30秒提供一条可用方法、关注理由更早出现、
  分平台测开场、精简同题材版本”。前5秒/5–15秒等时间只是测试方案，不能变成所有视频的固定卡点。

## 先观察、再决定

1. 保存当前快照/版本，区分**已确认制作要求**、**本次可见数据事实**、**待验证解释/编辑假设**。
2. 用户要求先观察时只读后续数据，保持现有作品、封面与排期；记录草案而不立即应用。
   观察本身不自动创建定时监控；已有监控沿用授权范围，另要定期跟进时先明确时间/频率。
3. 后续有新数据再比较同窗口表现或明确标注的累计增量，关注早期留存、平均观看、原生点击和转粉；
   避免仅凭某一天多一两人关注就定规律。指标没有明显新信息时不反复建议改版。
4. 获准测试时一次只改变一个主要变量，事先写下假设、版本、排期、样本窗口和判断指标；
   同题材尽量可比，记录热点与发布时间差异。没有随机/受控实验时仍称观察结果，不承诺因果。
5. 明确事实/身份/使用依据缺陷单独报告；禁止播放的版权通知先保存证据，改封面不解决播放限制，
   申诉/重传/删除必须有对应授权。修复后版本另记，不能与正常作品混入流量结论。

交付包含逐平台数据表、主要入口/留存/涨粉特点、结论限制、待观察假设，以及证据和采集时间。
不把建议写成已实施改动，也不声称在没有工具/任务运行时正在持续监控。
